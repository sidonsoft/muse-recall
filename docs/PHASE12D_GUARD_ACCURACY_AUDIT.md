## 1. Corpus description

`tests/evaluation/forge-decision/accuracy/`

| Asset | Purpose |
| --- | --- |
| `decisions.ts` | Hand-written decision fixtures (active, superseded, expired, multi-history, non-correction, negation-scope). Synthetic provenance, ids prefixed `12d-`. |
| `corpus.ts` | **72 synthetic source fixtures**, one rule under audit each, covering every required dimension per rule: clear violation, clear compliance, ambiguous, inert comment (line/block/HTML), inert string, renamed identifier, alternate implementation, formatting variation, multiple constructs, relevant/irrelevant memory decisions, decision-linking, negation scope, missing provenance. |
| `authentic.ts` | **5 cases against the authentic Muse artifact** `experiments/muse-forge/game/index.html` (sha256-pinned: `34bc91e5…a93d`, 26,260 bytes, commit `f751233`, generated by `muse-wonder-1.0` / Muse Code 1.4.13 per `docs/MUSE_FORGE_FEASIBILITY.md`). Read-only input; the test **fails if the artifact changes**, so it can never silently drift or be hand-edited into a nicer result. Decisions paired with it are auditor-written; the provenance claim covers the source file only. |
| `harness.ts` | Runs each case through the pure engine, classifies against auditor ground truth, computes per-rule metrics. |
| `accuracy.test.ts` | 40 tests: golden per-case rows + confusion metrics (vitest snapshots), **explicit pinned FP/FN case-id sets** (any engine change that moves a case between TP/FP/FN/TN fails), 14 security probes, determinism, non-mutation, size caps. |
| `__snapshots__/` | Committed golden records of engine behaviour. |

Ground truth is adjudicated by reading each fixture (documented per case in `notes`),
independent of the engine. Engine verdicts are recorded separately; TP/FP/TN/FN are derived,
never asserted by hand-picking engine output.

### Classification conventions

- `BLOCK` = engine predicts violation. `PASS` = engine claims compliance.
- `UNVERIFIED` / rule-not-fired = **ABSTAIN** — no claim, excluded from precision/recall,
  reported as an `abstention_rate` instead. Abstention on a violation is *safe coverage loss*,
  not a false negative.
- A **false negative (FN)** requires the engine to *claim compliance* (PASS) on a violation.
- `UNSOUND_PASS` / `OVERBLOCK` — PASS or BLOCK on fixtures whose compliance is not
  decidable by inspection; currently zero PASS-claims on indeterminate fixtures.
- Zero denominators are reported as `null` → “n/a” (never 0 or NaN).
- `unsafe_block_rate` = blocks fired on non-violating fixtures ÷ all blocks fired: the
  probability that an automatic block would have been wrong on this corpus.

Corpus size: **72 synthetic cases + 5 authentic-source observations + 14 security probes.**
Hand-built and adversarial by design: metrics quantify the fixture set, **they do not
statistically generalise to model output in the wild.**

## 5. False negatives and coverage gaps

FN = engine *claimed compliance* on a violation:

| Case | Rule | Why the engine missed it |
| --- | --- | --- |
| A09 | countdown | `secsLeft -= 1` — renamed identifier, no token |
| A10 | countdown | `remaining = Math.max(0, remaining - 1)` — alt construction |
| B05 | flashing | `tweens… yoyo: true, repeat: -1` alpha pulse (engine's own comment admits the gap) |
| B08 | flashing | rAF sine-driven `globalAlpha` |
| B09 | flashing | `Phaser.Actions.ToggleVisibility(tiles, 6)` |
| C07 | penalty | `points = points - 5` — renamed counter |
| C08 | penalty | strikes→endRound penalty without score token |
| D07 | palette | `#FF7E47FF` 8-digit hex — `\b` after 6 digits fails on 8-digit RGBA |
| D14 | palette | Two superseded records; engine inspects only the **first found** |
| E10 | colour | Unrelated `shape: 'rounded'` inside the 160-char window → spurious narrow **PASS** |
| E11 | colour | `"solid purple"` — the word *solid* counts as a non-colour cue → spurious narrow **PASS** |

Coverage losses that abstain instead of lying (safe but real gaps):
A14 (decision phrased "never show seconds left" — no `countdown` token), C14 (decision uses
the verb *penalise*; the matcher only knows the noun `penalt\w+` — genuine matcher gap),
D10 (family-words-only history can't hex-match), **D12 (`0xff7e47` in source vs `#FF7E47`
in the record: notations are never cross-matched — the engine's own 0x hex support leaks
across rules)**, D13, E06, E07 (`0x00FF00`/`0xFF0000` numerics aren't in the red/green token
list), E03/E12.

Aggregate soundness issue (E13): a decision worded "red/green-only pairs" without the word
"colour" links only the flashing rule; the flashing check PASSes and **the decision's overall
verdict becomes PASS even though the colour axis was never evaluated**. Aggregate PASS is not
"fully verified".

## 6. Security & robustness findings

Probes S01–S13 (`accuracy.test.ts`), all passing on v1.1.0:

| Area | Result |
| --- | --- |
| Input size | `MAX_SOURCE_CHARS = 400 000` enforced inclusively; oversized → UNVERIFIED + `source_oversized` warning; findings never emitted on oversized input (S01). |
| Caps | 32 decisions (S02) and 64 findings (S03) enforced and disclosed via warnings. Note: on cap hit, evaluations are silently truncated to the first 32 by decision-id order — the *dropped* decisions leave no per-decision trace beyond one warning. |
| Regex complexity | All quantifiers bounded/linear; comment masker is a single linear pass. Measured: **5.8 ms** for a 400 KB near-miss source (S13 asserts < 2 s CI margin). No catastrophic backtracking surface. |
| Malformed decisions | null/non-object/missing-field/non-array-`superseded` all rejected with warnings; never guessed (S04). |
| Duplicate ids | Not deduplicated — duplicate findings for duplicate decision objects (S05). Harmless to verdict, noisy for issue lists; dedupe at integration. |
| Provenance | Non-active statuses excluded from enforcement (`excluded_decision_ids`) and never PASS (A13/B12/C13/D13); palette without history supplied stays UNVERIFIED (D05). |
| Unicode | NBSP still matches (`score\u00A0-= 5` blocks); **zero-width space defeats the penalty pattern** (`score\u200B-= 5` → PASS, S06) — an obfuscation vector, low risk for generated (not hostile) source. |
| Embedded HTML | Attribute values count as source: `data-tip="countdown"` → BLOCK (over-block risk, S07); inline styles `color:red`/`color:green` correctly evaluate for rule E. |
| Determinism | Byte-identical JSON across repeats and across input-order permutations of the decision array (S10); inputs never mutated, including `options.supersededDecisions` (S11). |
| Execution safety | Engine is pure: no IO/eval/network/shell; fixtures are string data and are never imported/executed. The audit never ran the game source. |
| Secret leakage | Evidence slices carry up to ±40 chars of raw source around each match — an adjacent API key appeared verbatim in `finding.evidence` (S09). **Integration must treat evidence as untrusted/redactable text.** |
| Masker limits (v1.1.0) | `//` inside regex literals can over-mask to EOL; apostrophes in HTML text nodes under-mask that line (safe direction). Both documented at the function. |

## 7. Targeted fix implemented (only engine change of this audit)

**v1.1.0 — string-aware comment masking** (`maskCommentBodies` in
`packages/decision-guard/src/index.ts`): before any source-side matching, the bodies of
`//`, `/* … */` and `<!-- … -->` comments are replaced with spaces.

- Fixes the dominant FP class (inert comments) for rules A–E in one narrow mechanism:
  6 FPs → TN, 1 FP → ABSTAIN, **zero regressions**: TP/FN sets byte-identical, all 19
  original 12B acceptance tests pass unmodified, authentic observations unchanged.
- Offset-preserving → evidence still sliced from original source (regression-tested).
- String-aware → CDN URLs (`https://cdn…`) never mistaken for comments (regression-tested).
- Pure, linear, no API surface added (function is module-private); GUARD_VERSION bumped
  1.0.0 → 1.1.0; behaviour documented at the function and in the header.
- Regression coverage: 9 new engine tests in `decision-guard.test.ts` + 7 pinned corpus
  rows in `accuracy.test.ts`.

**Deliberately not fixed** (documented instead, per the brief): string/prose FPs (fixing
them needs string-vs-styling semantics; stripping strings would break rules D/E where hexes
in strings *are* the styling); decision negation-scope (B14/S08 — needs clause parsing);
token-coverage FNs (adding tokens lowers recall cost but raises FP — tuning would overfit a
hand-built corpus); `penalt\w+` verb gap, 0x/# equivalence, multi-history only-first-found,
8-digit hexes (each is a rule-semantics change, not a narrow fix; recommended as policy
guardrails instead).

## 8. Recommended enforcement policy (rule by rule)

| Rule | Recommendation | Basis |
| --- | --- | --- |
| `superseded-palette` | **BLOCK** (only when `options.supersededDecisions` supplies the replaced record) — otherwise UNVERIFIED surfaces. Keep a human override path for hex-in-prose strings (D04). | Highest signal: exact-hex evidence is concrete (M04 authentic TP). Remaining FP rate 0.25 FPR / 0.20 unsafe-block driven by one contrived changelog case. |
| `countdown-mechanics` | **BLOCK narrowly**: only findings whose evidence shows a code decrement/token form (`timeLeft`, `timer -= n`, `countdown--`, `countdown` as identifier). **ADVISORY** for word-only hits in text strings (A08). | Code-shape matches were 4/4 correct; the single FP is a bare word in a string. Cloud-side evidence filter keeps the pilot precise. |
| `mistake-penalty` | **ADVISORY** (never auto-block). | `score -=` precise, but identifier-substring (C09) and UI-string (C06) FPs plus matcher gaps (penalise verb, renamed counters) make both directions unreliable. |
| `flashing-effects` | **ADVISORY** (never auto-block). | Worst FPR-class for legitimate motion (ticker B13), decision-scope FP (B14), and it *misses the dominant Phaser flash pattern* (tween pulses) — blocking punishes correct code while letting real flashes through. |
| `colour-only-cue` | **UNVERIFIED-first; BLOCK findings are ADVISORY only; narrow-PASS must never be treated as verified compliance.** | Both outputs unreliable: narrative-string FP (E05), spurious PASSes from proximity words (E10/E11: `shape`, `solid`). 46% abstention. Genuinely semantic. |

Additionally, independent of rule:

- **Aggregate `PASS` ≠ verified** whenever any axis of a decision is UNVERIFIED or not
  linkable (E13). Server logic must consume per-rule evaluations, not just the verdict.
- UNVERIFIED notes are always safe to surface (advisory to the reviewer) and recommended.
- Never enable enforcement for decisions the engine cannot link (none-applicable).

## 9. Overall verdict — GO / NO-GO for server-side enforcement

**NO-GO for blanket automatic blocking** of Guard findings at the approval gate. On an
adversarial corpus tuned to this engine's own semantics, 1–3 blocks in 4 (v1.0.0) and still
1 in 4–6 (v1.1.0) would have stopped a legitimate change — the failure mode the brief calls
serious.

**CONDITIONAL GO — two-part pilot, behind a human-review lane:**

1. **Surface everything** (issues + `unverified_notes`) into `job.validation.issues` /
   review UI immediately: advisory-only, no gate effect. Zero false-enforcement risk.
2. **Auto-block only** (a) `superseded-palette` hex findings with provenance supplied, and
   (b) `countdown-mechanics` findings matching the code-shape allowlist, with reviewer
   override. Rules B/C/E stay advisory. Add secret redaction and finding dedupe first.

Re-evaluate the pilot against real generated traffic (log-only mode) before widening.

## 10. Integration advice for the cloud agent

1. Call `evaluateDecisions(activeDecisions, generatedSource, { supersededDecisions })` after
   the job's final source exists and before the approval gate; feed the **full file text**
   (the engine self-limits at 400 KB and returns UNVERIFIED beyond it — never PASS).
2. Consume per-rule `evaluations`, not just `result.verdict`; do not let an aggregate PASS
   clear an UNVERIFIED axis (E13).
3. Apply the §8 rule allowlist in the **cloud policy layer** before mapping findings through
   `toValidationIssues()`; keep `blocks_approval` semantics of the engine intact.
4. Always supply `supersededDecisions` for palette corrections — otherwise rule D can only
   abstain and the strongest signal is lost.
5. Cap inputs server-side too (≤ 32 relevant active decisions; sort by relevance — the
   engine's truncation is by id order, not relevance).
6. Redact/scan evidence strings before persisting into issues (S09 showed adjacent secrets
   survive verbatim); 160-char cap already bounds size.
7. Dedupe findings by `(decision_id, rule)` — duplicate decision objects produce duplicate
   findings (S05).
8. Record `engine_version` with every job's guard result; pin the version in the job record
   so audits remain reproducible (v1.0.0 and v1.1.0 behaviour differ on comments).
9. Never evaluate guard verdicts inside a model-retry loop as ground truth — retry only on
   allowlisted BLOCK findings; treat UNVERIFIED as reviewer context, not model feedback.
10. Keep the engine out of any path that executes or imports generated source; it is pure
    string analysis by contract.

## 12. Remaining limitations

- Metrics come from a 72-case hand-built adversarial corpus plus **one** authentic artifact:
  they quantify fixture behaviour, not production model output; no statistical
  generalisation is claimed. Corpus deliberately oversamples edge classes.
- Ground truth on ambiguous fixtures (A05, C04, E10) is auditor judgement; notes flag the
  arguable ones.
- Authentic category n=1; a wider corpus of Forge-generated files would strengthen rule
  observations, especially B (tween pulses) and D (palette drift).
- All §5 coverage gaps and §7 "not fixed" classes remain open in the engine by design;
  §8 policy contains them rather than the engine.
- Security posture assumes decisions come from the project's own memory store; decision
  text participates in regex matching (linear, bounded) but is not executed.
