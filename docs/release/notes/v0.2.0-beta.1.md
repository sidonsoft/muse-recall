# Draft release notes: v0.2.0-beta.1 (first post-judging promotion)

**Status: draft. Not to be tagged, released or promoted to `main` before judging closes.**
This describes what `integration` would bring to `main` in the first promotion after
judging. Numbers were taken from `integration` at `a11af5c` (31 Oct 2026); re-run the
count commands below at promotion time and update them.

Suggested tag: `v0.2.0-beta.1`, published as a **pre-release**. Version strings stay at

## Highlights

Muse Recall 0.2.0-beta.1 is the first release after the hackathon. It is still a local,
single-user beta, now hardened for longer-running use and opened up to other tools.

**Integrations**
- MCP stdio server over one shared, versioned tool contract (seven tools, including the
  `memory.graph` read tool). (#45, #58)
- REST traversal with real pagination totals and a machine-readable error catalogue at
  `GET /api/errors` (catalogue v2). (#51, #61)
- `Idempotency-Key` replay on memory creation and Forge generation (24h, durable across
  restarts). (#52)
- Optional shared bearer token so the server can be exposed deliberately; loopback stays
  the default. (#47)

**Memory**
- Memory record contract: revision, actor and proposed lifecycle. (#39)
- Portable memory export/import with versions and round-trip checks. (#40)
- Review queue for stale claims, plus a timeline and relationship map in the Memory view. (#46, #56, #57, #59)

**Reliability and operations**
- Forge `state_corrupt` inspect and repair path, wired into the Studio banner. (#32, #33)
- Power-loss-safe Forge writes (fsync before rename, directory sync after). (#35)
- Store-wide Forge recovery summary in health and the System screen. (#36)
- Backup restore path with a standing drill; operator runbooks for upgrade, rollback,
  incident and disaster recovery. (#49, #53)
- Alert signals in `/api/health` and a cron-ready alert prober. (#54, #55, #63)
- Forge worker isolation seam (`FORGE_WORKER_WRAPPER`). (#44)

**Quality**
- Decision Guard covers autoplay media and external assets (v1.5.0, still advisory). (#42)
- Managed browser workflow: Firefox leg, accessibility checks, interrupted-job scenario,
  visual snapshots. (#41, #43)
- Adversarial boundary suite for the access-control layers. (#50)
- Zero Biome warnings repo-wide; CI actions pinned to commit SHAs; CI re-verifies the
  locked research chain on every push. (#64, #249, #251)

**Documentation**
- Post-hackathon roadmap, SECURITY.md, issue forms, contributing guide, capability
  inventory, and the submission preservation manifest. (#29, #30, #31)
- Roughly 170 audit PRs (#65 onward) re-verified docs, counts, links and live wire
  behaviour against the code; see DEVELOPMENT_LOG.md and the archived cadence journal.

## Breaking or notable changes

- Database schema moves to v8 (idempotency records). Migrations run on start; take a
  backup first (`pnpm db:backup`).
- The legacy raw `memoryBlock` input was removed from production prompts. (#37)
- Error catalogue v2 changes two error codes that v1 pinned (D054).

## Known issues carried into this release

- KI-43, KI-45, KI-48: error catalogue gaps (malformed JSON and oversized bodies answer
  `internal_error`). The fix is queued as one lockstep PR (catalogue v3) immediately
  after judging.
- KI-49: true uid isolation of the Forge worker needs an ACL change (owner call).
- Tests are executed in CI but not typechecked (186 errors measured; plan in NEXT_STEPS B-7).
