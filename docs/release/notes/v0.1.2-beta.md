# Muse Recall v0.1.2 beta

This patch includes the Codespaces onboarding changes from #284, which were not part of v0.1.1. Existing releases and assets remain preserved.

## What changed since v0.1.1

- Start the app once on container start; reattaching only prints links, status and the read-only readiness command.
- Preserve existing demo state, jobs, staging, arbitrary project files and `.env`; match the seed's exact workspace path semantics and refuse automatic seeding of a different `SEED_PROJECT` target.
- Serialize normal and stale-lock recovery starts. Stop only the recorded app tree, including children that ignore termination after their parent exits.
- Install browser system libraries separately from the application-user Chromium download and launch check. Driver timeouts clean up failed launches; recovery commands keep downloads out of root's cache.
- Keep Muse CLI installation explicitly opt-in. Device login, live generation and live media remain experimental and unverified in Codespaces.
- Reconcile the judge guide and website with the new lifecycle, and align package/API/MCP versions to 0.1.2.

## Try it

Requires Node.js 24+ and pnpm 10.x (workspace pin: 10.32.1).

```sh
git clone --branch v0.1.2 https://github.com/sidonsoft/muse-recall.git
cd muse-recall
pnpm install --frozen-lockfile
pnpm judge:check
pnpm demo:seed
MODEL_PROVIDER=echo pnpm dev
```

Open http://127.0.0.1:5173. Offline exploration supports browsing and chat, not Studio application generation. Re-running the seed resets the demo workspace. Live generation requires an installed, logged-in Muse Code CLI and a verification browser; media operations require a separate server-side `FORGE_MUSE_API_KEY` and quota.

## Verification and release identity

The GitHub release records the exact tagged commit and links its CI. Attached source and verification evidence belong to that commit; `SHA256SUMS` identifies the published assets. ## Limits

Single-user local beta, loopback by default, optional shared bearer access, no accounts or hosted collaboration, and one generated HTML document per application. Guard and screenshot findings are advisory. Approval checks loading, not every interaction, accessibility or output quality. Live inference sends selected inputs to the provider and may incur charges. Codespaces generation has not been exercised. Existing Vite/esbuild development-tool advisories remain separate maintenance. A fresh cloud Codespace was not exercised: the connected GitHub token lacks the Codespaces permission. Lifecycle claims are supported by local and Linux-CI disposable-process tests, not a cloud create/reattach witness.

This release does not modify a hackathon entry or identify the unknown original submitted tree. Frozen tags and checksummed research/demo evidence are unchanged.
