# Muse Recall v0.1.0 beta

Muse Recall is a local-first studio for building small browser applications with project memory you can inspect and correct. Remember the brief, bring references, review the change and keep the approved application with its history.

This first beta combines the full integration functionality with a product-first README and a three-minute demo. It is a single-user application; loopback is the default, with optional shared bearer access and no user accounts or hosted collaboration.

## Try it

Requires Node.js 24+ and pnpm 10.x (pinned to 10.32.1).

```sh
git clone --branch v0.1.0 https://github.com/sidonsoft/muse-recall.git
cd muse-recall
pnpm install --frozen-lockfile
pnpm demo:seed
MODEL_PROVIDER=echo pnpm dev
```

Open http://127.0.0.1:5173. The offline path needs no provider credential and supports browsing and chat, not application generation. Re-running the seed resets the demo workspace. Real generation needs a logged-in Muse Code CLI and the approval browser; media operations need a separate server-side API credential. See the [README](https://github.com/sidonsoft/muse-recall/tree/v0.1.0#quick-start).

## What is included

- **Correctable project memory:** decisions with provenance and revision history, supersession, bounded retrieval, review queue, timeline, relationship map and versioned memory export/import.
- **Reviewable application generation:** staged Preview, Source and Changes; approve/reject; immutable versions and ancestry-based rollback; exact-byte copy/download; syntax and load-time browser checks.
- **Media references:** image upload, generation and editing; approved image embedding with integrity records; SAM cutouts; vision-proposed decision drafts; voice/video source upload and playback, transcription and clip observations.
- **Screenshot review:** compare a preview frame with selected decision revisions. Findings remain advisory and do not publish an application or write memory.
- **Decision Guard and dependencies:** seven advisory source-pattern rule families, bundled supported Phaser, and disclosure of bundled, remote and blocked dependencies.
- **Integrations and operations:** seven shared application/MCP tools; REST traversal and error catalogue; supported idempotent writes; durable jobs and restart recovery; database/media backups, restore drills, health alerts and damaged-state inspection/repair.

## Verification and evidence

The release assets include the final production gate report with its commit and bundle hashes, a source archive and SHA-256 checksums. Ten offline gates exercise workflows using deterministic providers; they do not measure generated-application quality. CI runs lint, product/test typechecks, unit/integration tests, managed Chromium and Firefox workflows, and research evidence re-verification. The website has separate build, link and browser checks.

Phase 17 retains 480 pre-registered runs across two models and six fixed strata. Original-rule violations among usable runs fell from 37/57 to 0/58 on Spark and 49/60 to 1/60 on Spark Open with retrieved memory. Eight Spark runs hit the time cap. These results cover fixed source-pattern tasks, not runtime safety, general application quality or the expanded media workflows. Research records and frozen tags are preserved.

The demo combines retained live correction footage, real provider-returned media, current beta UI replays and labelled test fixtures. The model needed an explicit request to apply the corrected palette; memory does not guarantee compliance.

## Limits

One generated HTML document per application. Advisory Guard and screenshot findings require human judgement. Approval checks loading, not correctness, accessibility or every interaction. Selected inputs leave the machine for live inference; the CLI runs under the server's local user and its own controls. Exported HTML runs outside the Studio sandbox. Provider access, latency, cost and quota affect live features.

The retained Palette Bench example has four open application findings. Its human quality sheet remains unscored; release authorization is not a quality score for generated output. See [limitations](https://github.com/sidonsoft/muse-recall/blob/v0.1.0/docs/guide/limitations.md) and [known issues](https://github.com/sidonsoft/muse-recall/blob/v0.1.0/docs/KNOWN_ISSUES.md).
